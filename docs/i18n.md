# Languages: German and English

Every account has a language, `de` or `en` (`users.locale`). It applies to
everything Gelabber itself writes: both clients' interface, Web Push texts
and account mail. Other people's messages are never translated. German is
complete; English is British English ("Colour scheme"), with dates and
numbers formatted as `de-DE` / `en-GB`.

Names stay as they are in both languages: "Gelabber", "Go Live", the theme
preset names ("Gelabber Dunkel"), server, channel and user names, and URL
slugs (`/settings/darstellung`).

## Where the language comes from

- **Signed in:** the account's language, the same on every device. It comes
  with the session user (`user.locale`), changes through
  `PUT /api/me/locale`, and reaches the account's other tabs and devices as
  the gateway frame `{"op":"lc","l":"en"}`.
- **Signed out:** the language the device last showed
  (`localStorage["gelabber.locale"]` on the web), else the browser's first
  German or English language, else English.
- **New accounts:** registration sends the language the device shows.

On the web, `index.html`'s inline script picks the language before the first
paint and sets `<html lang>`; the splash carries both languages and CSS shows
the chosen one (the shell's CSP allows that one hashed inline script only).
`src/i18n/startup.ts` hands the choice to the store before React renders.
`public/offline.html` makes the same choice between two text blocks.

## Catalogs

A **namespace** is one file per client, owned by one work batch at a time:

- web: `web/src/i18n/catalogs/<namespace>.ts` (lowerCamelCase file name);
- native: `desktop/i18n/src/<namespace>.rs` (snake_case).

Web and native use the same namespace names where the areas match, but keep
separate files.

A web catalog file exports one catalog under the file's name:

```ts
import { defineCatalog } from "../catalog.ts";

export const callBar = defineCatalog(
  "callBar",
  {
    leave: "Verlassen",
    muteLabel: "Mikrofon stummschalten",
    people: { one: "{count} Person", other: "{count} Personen" },
    help: "Mehr in der <link>Hilfe</link>.",
  },
  {
    leave: "Leave",
    muteLabel: "Mute microphone",
    people: { one: "{count} person", other: "{count} people" },
    help: "More in the <link>help</link>.",
  },
);
```

and code reads it with:

- `useT(catalog)` in components: `t("leave")`, `t("people", { count })`. It
  renders again when the language changes.
- `translate(catalog, key, params)` outside React, in the current language.
- `<T catalog={callBar} k="help" tags={{ link: (text) => <a …>{text}</a> }} />`
  for rich text.
- `useCurrentLocale()` for the language itself in a component. Prefer it to
  `useLocale(selector)`: a server render (`renderToStaticMarkup` in tests)
  sees the current language with it, not the store's initial one.

### Rules

- **Keys** name what the text is for, not what it says:
  `<surface>.<element>[.<variant>]` in lowerCamelCase segments, matching
  `^[a-z][a-zA-Z0-9]*(\.[a-z][a-zA-Z0-9]*)*$`. Accessible names end in
  `Label` (`callBar.muteLabel`). `abbrechen` is wrong. Natively the same key
  becomes a snake_case function (`call_bar_leave()`).
- **Placeholders** are `{name}`. Numbers passed as parameters are formatted
  in the language (`1.234` / `1,234`); pass a string when a number must not
  be. Both languages use the same placeholders.
- **Plurals** are `{ one, other }` and need the `count` parameter
  (`Intl.PluralRules`). A different sentence for zero ("Niemand schaut zu")
  is its own key.
- **Rich text** marks inline elements as `<link>…</link>`, `<b>…</b>` or,
  on the web, `<code>…</code>`: no attributes, no nesting.
- **Text kept outside a render** (a toast, an error in a store) is taken
  when it is made and keeps that language. Text a module would fix when it
  loads is read when it is shown instead: `lazyPart` takes its failure
  sentence as a function, `() => translate(ns, "key")`.
- **Formatting** of dates, times, relative times, numbers and name sorting
  goes through `web/src/i18n/format.ts` (`formatDate`, `formatTime`,
  `formatRelative`, `formatNumber`, `compareNames`) or
  `gelabber_i18n::intl` natively. Only `i18n/locale.ts` names `"de-DE"`.
  Search folding (`toLocaleLowerCase()`) stays locale-neutral.
- **Informal German "du"** becomes plain "you".

### What checks them

- `npm run build` (`tsc`): English has exactly the German keys, a plural is
  a plural in both, a key exists, and every placeholder is filled in.
- `npm test` (`src/i18n/catalogs.test.ts`): for every file in `catalogs/`,
  the export and `ns` match the file name, keys are well-formed, both
  languages have the same keys, placeholders, tags and plural forms, and no
  text is empty. A new namespace file is found by itself; nothing registers
  it. The catalog checks live in `npm test` and `tsc`, **not** in
  `npm run test:checks`.
- `npm run lint`: `gelabber/no-literal-ui-text`
  (`web/eslint-rules/no-literal-ui-text.js`) flags JSX text, string literals
  in the attributes `aria-label`, `title`, `placeholder`, `alt`, `label`,
  `description`, `hint` and `message`, and German-looking literals in the
  properties `label`, `description`, `hint`, `title`, `message`, `text` and
  `error`. `// i18n-ok` (or `{/* i18n-ok */}`) on the line exempts an
  intentional literal such as "Gelabber". Tests and the catalogs are not
  checked.

A key missing at runtime (only possible through a cast) shows the German
text and logs an error in development.

## Which namespace owns a file

The v0.10 English package moved the existing German text into catalogs, one
web namespace per area. A file's text lives in the namespace of its area:

| Files (under `web/src/`)                                                                                               | Namespaces                                   |
| ---------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `auth/**`, the signed-out pages (`AuthLayout`, `LoginPage`, `InvitePage`, `NotFoundPage`, …)                           | `auth`                                       |
| the settings pages and forms, `theme/**`, `interface/**`, `profile/**`, `pwa/**`, the notification settings components | `settings`, `themes`, `notifications`, `pwa` |
| `messages/**`, `gifs/**`, the message components (`Composer`, `MessagePane`, `MessageRow`, `EmojiPicker`, …)           | `chat`, `emoji`                              |
| the rest of `components/**` (incl. `ui/**`), `dms/**`, `ws/**`, `routes.tsx`, the workspace and DM pages               | `shell`, `dms`                               |
| `servers/**`, the server and community pages, `ServerSettingsPage`, the member and invite components                   | `servers`, `serverSettings`, `members`       |
| `voice/**` and the `Voice*` / `UserVolumeControl` components                                                           | `voice`, `voiceSettings`, `diagnostics`      |

`common` and `language` belong to the i18n core (`index.html`'s splash and
`offline.html` carry their own two texts). There are no allowlists: every
file under `web/src` passes the literal check, so mark an intentional
literal with `// i18n-ok` instead.

The native app gets the same namespaces in `desktop/i18n/src/`.

## Later packages

- A string in an existing file goes into **the namespace that owns the
  file** (table above): later packages add keys, in lowerCamelCase, to the
  namespace of the file they edit.
- A **new file** uses its package's reserved namespace: `roles`, `operator`,
  `account`, `discovery`, `public`. Call view uses `voice` /
  `voiceSettings`; sign-in uses `auth` / `settings`.
- Error-code copy is `auth` `error.<code>`, the code in lowerCamelCase.
- Server-side texts (push, mail, a new server's default channels) live in
  `backend/api/src/i18n/<area>.rs`; `Mailer::send(to, mail, locale)` takes
  the language explicitly.
